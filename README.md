# SQL Retail Analytics

Fifteen analytical SQL queries on a two-year e-commerce dataset — cohort retention, LTV by acquisition channel, conversion funnels, RFM segmentation, Pareto concentration and discount margin impact.

Every query in `sql/` has been executed and its **real output is committed in `results/`**, so you can read the answers without cloning anything.

> **On the data:** the dataset is **synthetic** — generated by [`data/generate_data.py`](data/generate_data.py), not scraped from a real store. I built the generator so the data has genuine structure to find (seasonality, channel quality differences, cohort decay, a Pareto tail) rather than being uniform noise. What's being demonstrated here is the analysis, not the data source.

**Scale:** 6,000 customers · 4,740 orders · 9,423 line items · 61,583 sessions · Jan 2024 – Dec 2025 · €624,907 revenue

---

## What the analysis found

**1. Paid social is the biggest channel and the worst one.**
It accounts for a third of all signups, but only **32.6%** of them ever place an order, against **58.3%** for organic. Average lifetime value is **€160 vs €282**. The funnel query shows why: paid_social converts cart-to-order at **1.3%**, organic at **3.5%** — the traffic reaches the cart at a normal rate and then doesn't buy. That's a traffic-quality problem, not a checkout problem.

**2. Discounts destroy more margin than they buy.**
Gross margin falls from **42.0%** on undiscounted orders to **26.6%** at a 20% discount, and discounted orders are *smaller*, not larger — average order value drops from **€131 to €110**. Across the four discount tiers there is no basket-size lift to justify the giveaway.

**3. Revenue is dangerously concentrated.**
The top decile of customers drives **34.7%** of revenue; the top three deciles drive **68%**. The bottom half contributes under 15%.

**4. The retention window is about six weeks.**
Of customers who order a second time, the median gap is **43 days** (p25 26, p75 70). A win-back campaign firing at day 60 is firing late. Overall repeat rate is **40.4%**.

**5. Coffee is the anchor, not the earner.**
Coffee has by far the most orders (5,847 lines) but only **18%** of revenue — Brewing Gear and Grinders together make **54%** off a third of the volume. Basket analysis shows Accessories+Coffee in **17.6%** of orders, which is the obvious bundle.

## The queries

| # | Question | SQL technique |
|---|---|---|
| [01](sql/01_monthly_revenue_growth.sql) | How is revenue trending month over month? | `LAG`, `date_trunc` |
| [02](sql/02_revenue_by_category.sql) | Which categories carry the business? | `SUM() OVER ()` for share-of-total |
| [03](sql/03_top_products.sql) | Top 3 products *within* each category | `RANK() PARTITION BY` |
| [04](sql/04_new_vs_returning.sql) | New vs returning revenue split by month | window `MIN` to label first orders |
| [05](sql/05_cohort_retention.sql) | Monthly cohort retention matrix | cohort join + month offset |
| [06](sql/06_ltv_by_channel.sql) | Which channel buys the best customers? | `FILTER`, `median` |
| [07](sql/07_rfm_segments.sql) | Who should marketing actually email? | `NTILE(5)` RFM scoring |
| [08](sql/08_conversion_funnel.sql) | Where do we lose people, by channel? | `FILTER`-ed funnel aggregates |
| [09](sql/09_aov_moving_average.sql) | Is AOV drifting once you smooth it? | `ROWS BETWEEN 2 PRECEDING` |
| [10](sql/10_repeat_purchase_gap.sql) | How long until the second order? | `LEAD`, `quantile_cont` |
| [11](sql/11_revenue_concentration.sql) | How Pareto is the customer base? | cumulative `SUM() OVER (ORDER BY)` |
| [12](sql/12_basket_affinity.sql) | What gets bought together? | self-join with `<` pair guard |
| [13](sql/13_churn_risk.sql) | How much revenue has gone quiet? | recency bucketing |
| [14](sql/14_discount_impact.sql) | Do discounts pay for themselves? | margin reconstruction from line items |
| [15](sql/15_channel_cohort_payback.sql) | How fast does each channel pay back? | cumulative window over a cohort grid |

Results for all fifteen: [`results/`](results/)

## Running it

```bash
pip install -r requirements.txt
python data/generate_data.py     # builds data/retail.duckdb  (~10s)
python run_queries.py            # runs all 15, refreshes results/
python run_queries.py 05         # run one query and print it
```

Requires Python 3.10+. No database server — [DuckDB](https://duckdb.org) runs in-process against a single file.

## Schema

Five tables — [`sql/00_schema.sql`](sql/00_schema.sql):

```
customers ─┬─< orders ──< order_items >── products
           └─< sessions
```

`sessions` carries the funnel flags (`viewed_product`, `added_to_cart`, `placed_order`) and links back to `orders` when a session converted.

## Notes on dialect

Written in DuckDB SQL. It is close to standard; on PostgreSQL the changes are `date_diff('month', a, b)` → age/extract arithmetic, and `quantile_cont` → `percentile_cont`. `FILTER (WHERE ...)`, `NTILE`, `LAG`/`LEAD` and the window frames all work unchanged.
